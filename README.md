# DocuChat

An AI knowledge assistant. Upload documents, ask questions in chat, and get
answers drawn only from those documents, with citations back to the source.

Answering from the model's own training data instead of the uploaded documents
is the specific failure this project is built to prevent. When the documents do
not contain an answer, the assistant says so rather than guessing.

## Stack

React + Vite + TypeScript, Express + TypeScript, MongoDB Atlas with Vector
Search, LangChain.js. Two AI providers are built in, selected with
`AI_PROVIDER`: Cloudflare Workers AI (Llama 3.3 70B and bge-base-en-v1.5
embeddings, the default deployment) or Google Gemini.

Generation and embeddings sit behind a provider interface in
`server/src/rag/provider.ts`. Switching to OpenAI means changing that one file.

## Running locally

Requirements: Node 20+, a free MongoDB Atlas cluster, and either a Cloudflare
account with a Workers AI API token (free daily allocation) or a Gemini API key.

```bash
# API
cd server
cp .env.example .env      # fill in MONGODB_URI, the AI provider credentials, JWT_SECRET, SEED_ADMIN_PASSWORD
npm install
npm run verify:vector     # confirms Atlas vector search works
npm run seed              # demo account and sample documents
npm run dev

```

`SEED_ADMIN_PASSWORD` sets the password for the admin account created by
`npm run seed`. It has no default and must be chosen by the operator.

```bash
# Web
cd client
cp .env.example .env
npm install
npm run dev
```

Create the vector search index on the `chunks` collection before first use:

```json
{
  "fields": [
    { "type": "vector", "path": "embedding", "numDimensions": 768, "similarity": "cosine" }
  ]
}
```

Name it `chunk_vector_index`.

## Tests

```bash
cd server
npm test              # unit tests, no credentials needed
npm run test:integration   # live Gemini grounding checks
```

## Deployment

The repository includes a Render Blueprint for the API (`render.yaml`); the
Vite SPA deploys to Cloudflare Pages. A free deployment is:

1. Create a free MongoDB Atlas cluster, create a database user, and allow the
   deployed API to connect. For a demo, Atlas's `0.0.0.0/0` access rule is the
   simplest option; use stricter network controls for anything beyond a demo.
2. Create a Cloudflare API token with the Workers AI template
   (dash.cloudflare.com/profile/api-tokens).
3. In Render, deploy the Blueprint from this repository. When prompted, set
   `MONGODB_URI`, `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN`, and
   `SEED_ADMIN_PASSWORD`. `JWT_SECRET` is generated by Render. The API health
   check is `/api/health`.
4. After the API deploys, copy its HTTPS `onrender.com` URL.
5. Build and publish the frontend to Cloudflare Pages:
   `cd client && VITE_API_URL=<api-url> npm run build` then
   `npx wrangler pages deploy dist --project-name docuchat`.
6. Open the deployed frontend, use **Enter demo** to smoke-test chat, then
   register the admin account only if you need to upload documents. Run
   `npm run seed` once against the deployed database if you want the bundled
   sample documents and demo account.

Render free web services sleep after 15 minutes without inbound traffic and
usually take about a minute to wake. Their filesystem is ephemeral, so MongoDB
must hold all application data. These are free-tier characteristics, not app
errors.
